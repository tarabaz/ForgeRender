# Contributing to ForgeRender

Contributions are welcome: bug fixes, performance improvements, rendering
research, importers, documentation, tests, and new features.

## Before opening a pull request

1. Open or find an issue describing the bug or proposed change. Discuss
   substantial features before implementing them.
2. Keep pull requests focused and explain the motivation, approach, and
   user-visible effects.
3. Add or update tests where practical. State clearly which tests you ran.
4. Run relevant checks, preferably:
   - `cargo fmt --all --check`
   - `cargo test --workspace --release`
5. Update documentation, the changelog, or technical reports when needed.

(including through a GitHub pull request or another project-managed channel),

you explicitly state otherwise or a separate written agreement applies.
This follows Section 5 of Apache-2.0.

You must have the right to submit the contribution under these terms. Do not
submit material copied from sources whose licenses do not permit its inclusion.
Identify third-party code, assets, and documentation and their licenses.

No separate Contributor License Agreement is currently required. The project
maintainer may request clarification about authorship, provenance, or licensing
before accepting a contribution.

## Review and integration

A pull request is a proposal, not a guarantee of acceptance. The project
maintainer reviews contributions and decides what is merged into the official
ForgeRender repository. Contributors retain copyright in their contributions;
accepted contributions are distributed under the applicable license terms.

Please be respectful, explain trade-offs, and include screenshots or render
comparisons when they help reviewers evaluate visual changes.
